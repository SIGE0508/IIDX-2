# Ver.1.2.0 リリース候補

公開待ち。公開版はVer.1.1.0。候補の基点は `39e10b7`、確認時の `origin/main` は `705e426`。後者は前者の祖先に含まれる。

## 変更内容

- TRACKERの譜面別NOTES RADAR展開と絞り込み条件の保持。
- NEXT TRAININGの候補を最大30譜面へ拡大し、複数の攻略目標を表示。
- WARM UPの3役割と独立した入れ替え。難易度とランプ条件はPhase 3の仕様を使用。
- NEXT PLAYでPLAYERごとに最大5譜面とメモを保存。
- 共通マスター2026.11.01、依存関係のセキュリティ修正、Phase 4の表示修正を含む。

## 公開前検証

- `npm ci`、自動テスト147件、TypeScript型検査、通常ビルドとPages向けビルドが成功。
- Pages向けPWAのmanifest、Service Worker、共通マスター5ファイルのオフライン取得を確認。更新待機、複数タブ、取得・インストール失敗時の旧版継続を隔離Edgeで検証。
- `v1.1.0`タグから作ったPagesビルドと候補のPagesビルドを同一のループバックURLで切り替えた。旧版を閉じて新版のバンドルを読み込んだ後、オフラインでHOMEが起動し、架空PLAYER、CLEAR、SCORE 123、BP 0、HISTORYを含むIndexedDB全7ストアの内容とDBバージョン2が維持された。
- JSONバックアップのschemaVersion 1を維持。旧バックアップの復元、NEXT PLAYを含む復元、復元失敗時のロールバックを隔離Edgeで確認。
- `npm audit`は既知の[GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)に由来する低4件。`npm audit --omit=dev`は0件。詳細は[残存リスク記録](SECURITY_RISK_DEEPMERGE.md)を参照。
- Android実機は未確認。公開後の確認項目は既存データの表示、standalone起動、オフライン再起動、タッチ操作。実機確認は公開前の必須条件から除外する。

## 手動公開手順

1. 公開承認後、最新の `origin/main` と候補の差分を再確認する。追加変更があれば統合後のコミットで検証をやり直す。
2. 承認済みの候補をmainへ取り込み、mainの対象コミットとパッケージのバージョンを確認する。
3. GitHub Actionsの **Deploy GitHub Pages** をmainから手動実行し、デプロイ成功と対象コミットを照合する。公開URLと `/IIDX-2/` のスコープを維持する。
4. 隔離ブラウザで公開版の主要画面とPWAを確認する。旧版が開いている場合は入力を保存し、同じアプリのタブとインストール済みウィンドウをすべて閉じてから開き直す。サイトデータ消去は不要。
5. 公開と確認が成功したコミットに `v1.2.0` タグを作成し、公開日と未確認項目をリリース記録に反映する。
6. 公開に問題があれば、公開前に控えた配布コミットをもとに復旧用コミットを用意し、同じURLへ手動で再デプロイする。候補版で保存したNEXT PLAYがある場合、旧版でプロフィールを保存する前に互換性を確認する。調査のためにIndexedDBを消去したり、旧バックアップで現在のデータを置換したりしない。
