# Phase 4：実PLAYERバックアップの安全な検証手順

現時点：実PLAYERバックアップ未提供。実PLAYERの推薦品質は未実施。
ツールの試運転は架空PLAYERだけで実施し、実データの実績とは区別する。

## 前提

- 開発版のPagesビルドを先に作る。公開版に変更を加える作業ではない。
- 通常の自動テスト、保存互換性、PWA、架空PLAYERのブラウザ回帰を先に実行する。
- Playwrightと利用するブラウザは既存の検証環境を使用する。依存追加は不要。
- 実バックアップは公開版Ver.1.1.0のDATAから利用者が取得し、
  Git管理外・共有同期外の私有フォルダに置いたコピーを指定する。
  バックアップ出力に伴う既存の日時メタデータ更新以外、公開版を操作しない。
- チャットへファイルを提供するか私有コピーのパスを知らせるかは、
  実データ検証を再開する際に利用者が選ぶ。今回は提供を求めず先行検証を完了する。

## 準備済みツール

scripts/verify-private-player.mjs

設定例（PowerShell。プレースホルダーは実際の私有パスに置き換える）：

    $env:GITHUB_ACTIONS = 'true'
    npm run build
    Remove-Item Env:GITHUB_ACTIONS
    $env:IIDX_PLAYWRIGHT_MODULE = '<既存Playwrightパッケージのディレクトリ>'
    $env:IIDX_BROWSER_EXECUTABLE = '<検証ブラウザの実行ファイル>'
    $env:IIDX_PRIVATE_BACKUP = '<Git外の私有コピー.json>'
    node scripts/verify-private-player.mjs
    Remove-Item Env:IIDX_PRIVATE_BACKUP

IIDX_PLAYWRIGHT_MODULEを省略した場合は通常のplaywrightを探す。
IIDX_BROWSER_EXECUTABLEを省略した場合はPlaywrightの既定Chromiumを使用する。
環境変数にPLAYER名・IIDX IDを設定する必要はない。
実データの出力をリポジトリのファイルへリダイレクトしない。

## ツールが行うこと

1. 入力がこのリポジトリや他のGit worktree内にないことを確認する。
2. OS一時領域へ専用ディレクトリを作り、元ファイルをコピーする。
   元ファイルは読取りだけで、改変・削除しない。コピーのハッシュを照合する。
3. 既存のparseBackup・validateBackupReferencesで事前検証する。
   複数PLAYERのバックアップは自動選別せず停止する。対象の確認が必要。
4. 127.0.0.1の専用ポートでローカルPagesビルドだけを配信し、新しい非永続
   ブラウザコンテキストを作る。外部オリジンへの通信とダウンロードを遮断する。
   この品質確認ではSWをブロックし、PWA検証は別の架空PLAYER環境で行う。
5. 起動直後にPLAYER・記録・HISTORY等が空、DB v2・7ストアであることを確認する。
   現行アプリは初回セットアップ中にDATAへ移動できないため、記録0件の
   使い捨てPLAYERを「後で登録」で作成する。これは既存DATA復元UIを開くためだけで、
   実バックアップの復元で完全に置換される。実記録の補完や混在には使わない。
6. 既存DATA復元UIで検証コピーを復元する。新機能やバリデーターの緩和は行わない。
7. 復元した6配列を、旧互換の既定値補完後のバックアップと全件照合する。
   初期PLAYERや下書きが残った場合は成功としない。
8. 同じ入力で純粋な既存推薦関数を計算し、HOMEの表示chartId・役割を照合する。
   乱数は0.5固定で再現可能にする。閲覧後に保存データが変化していないことも確認する。
9. PLAYER名・IIDX ID・全記録を出力せず、NEXTの候補数・目標別内訳・表示譜面、
   WARMの役割別候補数・表示譜面・難易度・ランプ・理由を利用者へ報告する。
   自動的な適格性確認と、利用者本人の「負荷が適切か」という評価を区別する。

## 終了・失敗時

ブラウザとサーバーを終了し、コンテキスト内のDB・キャッシュを破棄する。
検証専用一時ディレクトリだけを安全なパス確認後に削除する。
入力バッファも破棄するが、復元不能な安全消去を保証するものではない。
元の私有コピーは残し、ハッシュが変わっていないことを確認する。
強制終了・OS停止ではfinallyが実行されない場合があるため、その場合はOS一時領域の
iidx-private-validation-で始まる今回作成分だけを確認し、終了後に手動で破棄する。
他の検証や利用者のファイルを一括削除しない。

成功出力には、コンテキスト破棄・一時コピー削除・元ファイル不変の結果を含める。
失敗時は処理段階だけを表示し、生データや例外中のPLAYER識別子を出力しない。
詳細原因の追加調査は同じ私有環境内で行い、Gitへ実値を転記しない。

## 試運転の区別

架空バックアップで試運転する場合だけ IIDX_VALIDATION_KIND=synthetic を設定する。
出力は synthetic dry run; NOT real-player evidence と明示される。
この設定や架空データの成功を、実PLAYER検証の成功と報告しない。

実データによる「不適切な推薦の有無」「負荷の偏り」「本人の納得感」は、
バックアップ提供と本人の確認後に残る検証項目である。
