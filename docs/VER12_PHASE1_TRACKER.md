# Ver.1.2 Phase 1: TRACKER

アプリversionは1.1.0のまま。2026-11-03に実装・検証。

## 実装

- TRACKER専用のTrackerScreen / TrackerChartRowへ分離。他画面のChartLine、TRAINING、NEXT TRAININGは変更しない。
- 検索条件（公式レベル、非公式難易度、譜面種別、ランプ、VERSION、並び順、方向）と展開chartId集合はApp内のメモリ状態。PLAYER変更時も保持し、現在のrecordsで再絞り込みする。曲名検索はTRACKERを離れるとクリアする。再読み込みで検索条件・展開状態は初期化する。
- 共通マスターはIDのMapで一度結合する。RadarはsongIdではなくchartIdで参照する。未登録譜面を除外しない。確認済み0は0.00、欠損は—。
- QUICK INPUTボタンとRadar開閉ボタンは兄弟要素。開閉はnative buttonのEnter／Space、aria-expanded／aria-controlsに対応。複数行を展開でき、閉じた数値は操作・読み上げ対象から外す。
- 390px幅ではRadarを2列にし、長い曲名も折り返す。保存形式・マスター・依存定義・PWA更新方針は変更しない。

node --test tests/*.test.mjs、型検査、通常／Pagesビルド、各ビルドのPWAテストを実施する。追加8件はtests/ver12-phase1-tracker.test.mjs。既存80件と合わせて88件。既知のdeepmerge関連低4件と本番用依存0件を確認し、新規Advisory・経路変更・重大度上昇は許容しない。

## 実ブラウザ確認の再現手順

既存の利用者データを使わず、隔離したブラウザプロファイルと専用オリジンで確認する。通常ユーザーのサイトデータは削除しない。PLAYER変更は隔離環境のバックアップ復元を利用する。

1. HOMEのNEXT TRAININGを記録し、TRAINING・TRACKERとの移動だけで候補が変わらないこと。
2. 初期状態は折りたたまれ、ボタンが入れ子でないこと。
3. 開閉だけではQUICK INPUTへ移動せず、6属性が指定順で表示されること。実値0と欠損を区別すること。
4. Space／Enterで開閉でき、フォーカスが残ること。
5. 別譜面を複数展開し、HOME往復後も展開を保持すること。曲名検索だけは消えること。
6. 7つのフィルタ・並び順条件を組み合わせ、HISTORY等との往復で保持すること。
7. QUICK INPUTからキャンセルして戻っても条件と展開を保持すること。
8. 条件・開閉だけの操作でIndexedDB／localStorage／sessionStorageが変わらないこと。
9. 保存後も条件が残り、ランプが条件から外れた譜面は一覧から消えること。
10. CT_ID0631等のRadar欠損譜面も選択でき、展開すると6項目とも—となること。11月3日原本値は今回のマスターには追加しない。
11. 別PLAYERのバックアップへ置き換え、条件を保持しつつ新しい記録で結果が変わること。
12. 再読み込みでメモリ上の条件と展開だけが初期化され、PLAYER記録は残ること。
13. 390px幅で長い曲名の譜面を展開し、2列・横はみ出しなしを確認すること。

Edgeの隔離環境で上記13シナリオを確認。PWAは/IIDX-2/でのオフライン再起動、5マスター取得、更新待機、テスト用IndexedDB v2・7ストアの保持も確認。Android実機確認は未実施。
